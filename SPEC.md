# SPEC.md — Al-Zhilin.github.io

Личный сайт-визитка на GitHub Pages: обо мне, карточки проектов с детальными
страницами, контакты, админ-панель для редактирования контента без участия
разработчика.

## Стек

- Astro (SSG) + TypeScript
- Tailwind CSS
- Astro Content Collections для проектов
- Vitest для юнит-тестов чистой JS-логики
- Деплой: GitHub Actions → GitHub Pages (`actions/deploy-pages`)
- Node 20 LTS, npm

## Первый шаг (бутстрап)

Проект стартует с пустой папки. Первая фича — сама по себе:
`npm create astro@latest` в текущей директории (TypeScript strict,
Tailwind-интеграция через `npx astro add tailwind`), добиться, чтобы
`npm run build` проходил на шаблоне без ошибок. Это и есть первый
проверяемый чекпоинт всего прогона.

## Структура страниц

1. `/` — главная: hero-секция, "обо мне", сетка карточек проектов, контакты, футер.
   Hero — статичная заглушка (CSS-градиент), контейнер с id `hero-canvas`
   оставить пустым внутри — это гнездо под будущую 3D-анимацию, которая
   в этот прогон НЕ входит (см. "Вне скоупа").
2. `/projects/[slug]` — детальная страница проекта, генерируется из content collection.
3. `/admin` — админ-панель, client-side island. `noindex` в meta, не добавлять
   в навигацию сайта — доступ только по прямому урлу.

## Дизайн-система

- Тема: только тёмная (без переключалки).
- Палитра: фон около `#0a0a0a`, текст около `#f2f2f0`, один акцентный цвет
  на выбор Claude (например приглушённый синий) — применять
  последовательно во всех интерактивных элементах.
- Шрифты: основной sans-serif (Inter или системный стек), моно-акцент
  (JetBrains Mono) для тегов проектов, дат и технических деталей.
- Много воздуха, не более 4 размеров текста в шкале.
- Плоские поверхности, тонкие бордеры, без декоративных теней/градиентов
  на карточках.

## Админ-панель — подробно

- Вход: при заходе на `/admin` запрашивается GitHub fine-grained personal
  access token (права только на репозиторий `Al-Zhilin/Al-Zhilin.github.io`,
  только `contents: write`). Токен хранится в `sessionStorage`, никуда,
  кроме `api.github.com`, не отправляется.
- Форма "Проект": все поля схемы + кнопка "Импортировать из GitHub repo" —
  по имени репозитория тянет описание/topics/README через
  `GET /repos/{owner}/{repo}` и предзаполняет поля.
- Форма "Обо мне": редактирует `profile.json`.
- Сохранение = `PUT /repos/Al-Zhilin/Al-Zhilin.github.io/contents/{path}`
  с новым содержимым и автосгенерированным commit-сообщением.
- "Удалить проект" = `DELETE` того же API по пути файла.

## Acceptance criteria

Это же — критерии для `/goal` и для Stop hook:

- `npm run build` проходит без ошибок
- `npm run check` (astro check, TypeScript) — 0 ошибок
- `npm test` (vitest) — все тесты зелёные; минимум покрыты: генерация slug
  из title, сериализация формы проекта в frontmatter, парсинг ответа
  GitHub API при импорте
- Главная рендерит секцию "обо мне" и минимум 3 карточки проектов
- Каждая карточка кликабельна, ведёт на корректную `/projects/[slug]`
  с полным описанием
- Ссылки на резюме и контакты рабочие (не 404)
- `/admin` открывается и форма валидна (без живого теста реального коммита
  в GitHub — см. "Вне скоупа")
- Сайт задеплоен на GitHub Pages: `curl -s https://al-zhilin.github.io`
  возвращает 200 и содержит `name` из `profile.json`

## Вне скоупа (явно не делать в этом прогоне)

- 3D / скролл-анимация в hero — отдельная задача позже, когда определится
  концепция
- Автотест реального коммита из админки в GitHub (небезопасно гонять
  автоматически с реальным токеном) — только юнит-тесты чистой логики
- Кастомный домен
- Переключение тёмная/светлая тема
- Многоязычность / блог
